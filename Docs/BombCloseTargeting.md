# 근거리 BombGun 표적 판정

일반 몬스터의 캡슐과 메시가 Visibility 채널을 무시하고 있어 기존 커서 검사는 몬스터 몸을 통과해 뒤쪽 바닥을 선택했다. 특히 작은 피해 반경이나 움직이는 근접 표적에서는 보이는 몸과 실제 폭발 중심이 달라질 수 있었다. 실제 바닥을 직접 지정한 근접 피해 호출은 정상 적용됨을 먼저 확인했다.

`Source/LostArk/private/Player/LostArkPlayerController.cpp`의 `OnBomb`만 전용 표적 검사로 연결했다. `GetBombHitFromRay`는 자신의 Pawn을 제외하고 일반 Visibility 검사와 Pawn 객체 검사를 함께 수행한다. 벽보다 앞에 있는 살아 있는 몬스터를 직접 겨냥하면 그 발밑 바닥을 폭발 중심으로 선택한다. 바닥을 찾지 못하면 실제 몬스터의 표면 히트를 사용한다. 먼저 맞는 벽이 있으면 벽 판정을 유지하고, 몬스터가 없는 빈 바닥에서는 기존 지점 판정을 유지한다.

헤더 `Source/LostArk/public/Player/LostArkPlayerController.h`에 같은 레이 검사를 Blueprint·자동 검증에서 호출할 수 있는 함수 선언을 추가했다. 기존 클래스·프로퍼티 이름, 좌클릭과 이동 입력, 전역 충돌 프리셋, 피해량·반경·쿨다운·반동 규칙은 변경하지 않았다. 기존 C++ 파일의 혼합 인코딩은 무관한 바이트를 보존하며 변경 구간만 수정했다. 새 게임 애셋이나 에디터 설정은 필요 없다.

정식 `LostArkEditor Win64 Development` 빌드 통과. 검증 코드는 `Saved/MotionReference/check_near_bomb_targeting.py`, 결과는 `near_bomb_targeting_validation.json`에 기록한다. 기존 범위 피해 회귀 검증은 `check_bomb_damage.py`를 사용한다.

PIE 검증 통과: 플레이어와 몬스터 캡슐 사이 약 2cm의 밀착 상태에서 기존 조준 바닥 X=1121.35 대신 실제 표적 발밑 X=1061.0을 선택했다. 검증용 반경 20cm·피해 37에서 체력 1000→963, 기존 반경 300cm·피해 83에서 963→880을 확인했다. 범위 밖 몬스터는 1000을 유지하고 중복 `BombHit`에 추가 피해가 없었다. 실제 벽 뒤에 둔 몬스터를 레이 표적으로 선택하지 않고 벽 판정을 유지하는 것도 확인했다. 저장된 피해량 100·반경 300cm는 변경하지 않았다.

수동 마우스 입력·이동 중 표적·전체 웨이브 전투 회귀는 미실행이다. 검증은 실제 커서와 동일한 레이 판정 함수 및 실제 `BombAttack` 경로를 사용했다. PIE에서 몬스터 몸을 가리킨 채 BombGun을 사용하고, 벽 앞/뒤와 빈 바닥 조준을 비교해 수동 입력을 추가 확인할 수 있다.
